# Experimental Exynos AP live audio bridge

This is an opt-in candidate for j7velte (Android 11–12, Root helper UID 0). It is not a verified call-audio route. Unlike the capability-only V1, it configures real AP PCM streams and transports samples over the existing Tether audio protocol. Native setup is gated to an active cellular call and the previously observed mixer baseline. It never opens PCM2, 3 or 6 for streaming. The AP capture is PCM0; playback is PCM7 with PCM0 as an alternate. Native format is stereo S16_LE at 48 kHz; conversion to/from the negotiated 8/16/48 kHz mono codec is built in. The candidate uses the vendor call_forwarding_master mixer output and input selections with CH2 mixer disabled to reduce far-end loopback risk. This combination is a hypothesis, not a confirmed vendor use case.

Enable Root helper, verify UID 0, then choose Enable Exynos AP bridge in Android Audio settings before the call. Only test on your own handset with a consenting participant. Use a short non-emergency call, low listening volume, and confirm both directions independently. If silence, feedback or distortion occurs, end the call immediately. Disable the bridge or reboot if ordinary call audio is not restored. The helper does not change policy XML, SELinux, system partitions or the modem PCM. Mixer values are snapshotted, changes are limited to the exact observed baseline, and restoration is attempted on normal stop, setup failure, disconnect and runtime error. A forced kill or kernel crash can prevent restoration; reboot if needed. The native bridge is disabled by default and existing ADB/Root framework paths remain available.

The self-test report still labels this route experimental: PCM transfer is not proof of correct end-to-end voice routing. Do not treat successful CI or stream initialization as verified voice. If 48 kHz PCM setup or mixer changes fail, the ordinary handset path remains the fallback. No iOS change is required.
